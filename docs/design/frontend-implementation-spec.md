## 2. 页面结构

建议沿用现有 `frontend/src/App.vue + vue-router + ChapterReaderView.vue` 结构，不要更换技术栈。设计图对应到前端页面如下：

```text
BrowserWindow（浏览器窗口 / 应用外壳）
└── Page（页面容器，对应现有 ChapterReaderView 的 .page）
    ├── TopLeftEntry（收起后左上角保留的操作入口）
    ├── MultiFunctionBar（多功能栏，左侧竖条）
    │   └── UserBar（用户栏，位于多功能栏底部）
    │       └── UserMenuTrigger（省略号按钮）
    ├── MarkdownReader（核心阅读区，对应现有 .reader__main + .article）
    └── UserOverlays（用户相关浮层/页面）
        ├── SettingsPanel（用户设置页面）
        └── ProfilePanel（个人信息查看）
```

与现有代码的对应关系：

- 现有 `ChapterReaderView.vue` 已有顶部栏 `.topbar`、目录侧栏 `BookSidebar.vue`、正文 `MarkdownRenderer`、翻页器、404/错误态。
- 现有 `BookSidebar.vue` 是图书章节目录，不是设计图中的多功能栏，不能直接等同，需要新增多功能栏组件。
- 现有路由只有 `/books/:id/chapters/:chapterId` 和 `/:pathMatch(.*)*`，没有 `/settings` 或 `/profile`，是否新增路由见第 7 节待确认。
- 现有顶部栏已有“目录 / 收藏 / 复制链接”按钮，多功能栏新增后要明确职责分工，避免重复入口，见 TBD-01。

布局规则（按设计图坐标比例转述，不规定像素）：

- 页面容器占满浏览器窗口内部。
- 多功能栏固定在页面左侧，纵向排列。
- Markdown 阅读主区占据页面剩余宽度。
- 用户栏固定在多功能栏底部，省略号按钮在用户栏内。
- 收起态：多功能栏隐藏，阅读主区横向扩展，左上角保留一个独立小入口。

## 3. 组件划分

以下组件命名为建议名，前端实现时可按现有 `PascalCase + <script setup lang="ts">` 风格调整，但职责边界建议保留。

### 3.1 `AppShell / BrowserWindow`

- 职责：浏览器窗口级外壳，提供页面容器、全局提示挂载点，不处理业务数据。
- 输入：`route` 当前路由；无业务 props。
- 输出：`<RouterView />` 页面内容；全局 `ToastHost`。
- 交互事件：无直接按钮事件，只负责布局槽位。
- 状态管理：无本地业务状态。
- 与其他组件关系：父组件，包含 `MultiFunctionBar`、`MarkdownReader`、`UserOverlays`；现状可直接复用 `App.vue`。
- 现状：`App.vue` 已实现 `RouterView + ToastHost`，可沿用。

### 3.2 `MultiFunctionBar`

- 职责：左侧多功能栏容器，内容已明确为“导入文件后的文件资源管理器”。文件资源管理器使用树状数据结构，支持文件节点与文件夹节点层级展示；左下方提供一个小的 `+` 号按钮，点击后选择文件导入；文件夹通过拖入资源管理器导入；为空时不展示占位，直接空白。选择文件树节点后驱动 `MarkdownReader` 加载对应文档。
- 输入：`collapsed: boolean`（桌面端默认 `false` 即默认展开；移动端默认 `true` 即默认收起，见 TBD-03b）；`fileTree: FileNode[]`（树状数据，节点至少含 `id/path/name/type`，是否含大小/更新时间由前端定义）。
- 输出：`update:collapsed` 或 `collapse` / `expand` 事件；`selectFile` 文件选择事件；`importFiles` / `importFolder` 导入事件。
- 交互事件：`onCollapse` 收起；`onExpand` 展开；文件节点点击/文件夹展开；`+` 号按钮点击选择文件；拖放导入（规则见 FR-03b）。
- 状态管理：`collapsed` 需要跨组件共享，至少为页面级 `ref`，建议放入可复用 composable（例如 `useSidebarVisibility`）；已打开文件在刷新后保留、关闭页面后不保留，关闭前必须提示保存（见 FR-03c 与第 6 节）。
- 收起动画：已明确为平滑滑动过渡（位移类过渡，时长与缓动曲线由前端按常规取值并在实现中说明）。
- 与其他组件关系：父组件包含 `UserBar` 与左下方 `+` 号导入按钮；兄弟组件为 `MarkdownReader`；收起时通知 `TopLeftEntry` 显示；文件选择后驱动 `MarkdownReader` 加载对应文档。
- 现状：不存在，需新增；不要复用 `BookSidebar.vue`，后者是图书章节目录，仅可参考其列表交互。

### 3.3 `TopLeftCollapseEntry`

- 职责：位于顶部绝对左上角的操作入口。Logo 默认空白，仅预留形状与按钮位置，等待用户提供图片后再填充；图标已明确为三条线（汉堡菜单）。展开态和收起态均可见：展开态点击后收起多功能栏，收起态点击后重新展开多功能栏。
- 输入：`collapsed: boolean`；`visible: boolean`（恒为 `true`，两种状态下均显示）；`logoSrc: string | null`（当前为 `null`，预留）。
- 输出：`toggle` 事件（或 `collapse` / `expand` 事件）。
- 交互事件：`click` 切换多功能栏展开/收起。
- 状态管理：受 `MultiFunctionBar.collapsed` 驱动，不自持状态；需要无障碍 `aria-expanded / aria-controls`，`aria-label` 建议取“展开/收起多功能栏”，最终文案待用户图片与视觉稿确认（见 TBD-04b）。
- 与其他组件关系：与 `MultiFunctionBar` 联动，视觉上位于页面顶部绝对左上角，不属于多功能栏内部。
- 现状：不存在，需新增；现有移动端 `sidebar-toggle` 按钮行为类似但不等同，不可直接替代。

### 3.4 `UserBar`

- 职责：展示当前用户简要信息，承载省略号按钮。用户数据已明确来自后端接口（不再使用前端 Mock 用户）。
- 输入：`user`（后端接口返回的当前用户对象，具体字段待后端协同定义，前端先按 `nickname/username/avatar` 兼容展示并在实现中说明）；`loading: boolean`。
- 输出：`openMenu` 事件。
- 交互事件：点击省略号按钮打开滑出面板。
- 状态管理：用户信息为只读展示，菜单开闭为本地 `ref<boolean>`；用户数据通过后端接口加载，需处理加载态与失败态。
- 与其他组件关系：内嵌于 `MultiFunctionBar` 底部；触发 `UserMenu`。
- 现状：不存在，需新增。

### 3.5 `UserMenu`

- 职责：省略号按钮的下一步操作，提供“用户设置”和“个人信息查看”两个入口。已明确形态为滑出的面板；选择后为路由跳转（不是弹窗），设置页路由与内容后续另出一版设计图，路径待该设计图确认（见 TBD-13b）。
- 输入：`open: boolean`。
- 输出：`selectSettings`、`selectProfile`、`close` 事件；实际跳转由路由执行。
- 交互事件：点击菜单项执行路由跳转；外点击直接关闭；按 `Esc` 直接关闭。
- 状态管理：本地开闭状态；跳转后菜单关闭；焦点管理暂不做（已明确）。
- 与其他组件关系：由 `UserBar` 触发；跳转目标为 `SettingsView` / `ProfileView` 路由页。
- 现状：不存在，需新增。

### 3.6 `SettingsPanel`

- 职责：用户设置页面容器。设置页本次不做详细规格，后续另出一版设计图后再补；当前仅记录已明确范围：“更改背景色和支持背景自定义”（即阅读区/应用背景外观设置）。背景预设至少含浅色、深色、跟随系统默认三种；自定义背景方式为用户自行上传图片。载体已明确为路由跳转后的独立设置页面（不是弹窗），路由路径待后续设计图确认（见 TBD-13b）。
- 输入：当前背景配置对象，例如 `{ preset: 'light' | 'dark' | 'system', customImage?: string }`（具体结构由前端定义）。
- 输出：背景变更事件或路由返回事件；保存机制（即时生效还是点击保存）待后续设计图确认（TBD-07b）。
- 交互事件：选择预设备选背景、上传自定义背景图片、返回阅读页。
- 状态管理：背景配置本地状态；是否持久化、是否全局生效待后续设计图确认（TBD-07b）。
- 与其他组件关系：由 `UserMenu` 经路由进入；与 `ProfilePanel` 为并列路由页。
- 现状：不存在，需新增；本次不展开详细字段与校验。

### 3.7 `ProfilePanel`

- 职责：个人信息只读查看。用户信息已明确来自后端接口。
- 输入：后端接口返回的当前用户对象；字段清单待后端协同定义，前端先按常规字段兼容展示并在实现中说明。
- 输出：`close` 事件；可选 `goToSettings` 事件。
- 交互事件：关闭；可选跳转到设置页。
- 状态管理：只读展示 + 加载态/空态/失败态；数据源为后端接口。
- 与其他组件关系：由 `UserMenu` 经路由进入；与 `SettingsPanel` 并列。
- 现状：不存在，需新增。

### 3.8 `MarkdownReader`

- 职责：Markdown 核心阅读容器，管理三种模式切换和文档数据。已明确默认模式为所见即所得（`mode` 默认值为 `'wysiwyg'`）。
- 输入：`bookId`、`chapterId`、`markdown: string`、`mode: 'wysiwyg' | 'source' | 'preview'`（默认 `'wysiwyg'`）。
- 输出：模式切换事件 `changeMode`；所见即所得与源码模式的内容变更事件 `contentChange`（两者均已确认为可编辑）。
- 交互事件：切换模式标签；所见即所得编辑；源码编辑/复制/保存；预览只读浏览；滚动、翻页沿用现有行为。
- 状态管理：`mode` 为核心状态，建议放在页面级 `ref` 或 `useMarkdownMode` composable 中，是否随路由/query 持久化待确认（TBD-12b）；文档加载/空/错状态沿用现有 `ChapterReaderView` 的 `loading / ready / not-found / error`；未保存内容的脏状态管理待确认（TBD-12b）。
- 与其他组件关系：兄弟组件为 `MultiFunctionBar`；内部包含三个模式子视图；预览模式复用现有 `MarkdownRenderer` 能力（含 `sanitize/GFM/Shiki`）。
- 现状：部分存在。现有 `ChapterReaderView.vue` 已实现预览渲染（含 `allow-html + sanitize + GFM + Shiki`），但无模式切换，需扩展。

### 3.9 `WysiwygView` / `SourceView` / `PreviewView`

- 职责：
  - `WysiwygView`：所见即所得视图，已确认为可编辑，编辑器选型已明确为 TinyMCE。
  - `SourceView`：源码视图，展示 Markdown 原文，已确认为可编辑，且支持复制和编辑保存；编辑器是否同样使用 TinyMCE 还是使用代码编辑器，由前端按常规做法决定并在实现中说明。
  - `PreviewView`：预览视图，已确认为只读，复用现有 `MarkdownRenderer` 渲染和安全过滤配置（`allow-html + sanitize + GFM + Shiki`）。
- 工具栏（已明确，需含以下三类，细节待后续设计图或前端落案说明）：字体加粗/加细（“加细”按常规理解落为斜体，前端需在实现中明确标注）、导入导图、导入代码块。
- 输入：`markdown: string`；`WysiwygView` 与 `SourceView` 为可编辑，`PreviewView` 为只读。
- 输出：`contentChange`（`WysiwygView` 与 `SourceView` 需要；`PreviewView` 无）。
- 交互事件：模式标签点击切换；所见即所得编辑；源码复制/编辑/保存；保存触发条件与未保存提示仍有部分待确认（TBD-09b/TBD-10b）。
- 状态管理：由 `MarkdownReader` 统一持有 `mode`，子视图无独立模式状态；`mode` 必须同步到 URL（已明确需要 URL 记忆模式，规则见 TBD-12b）。
- 网络与保存失败：网络断开或服务器崩溃直接提示网络错误（已明确）；后续再设置轮询机制保证数据不丢失，轮询机制本次不做详细规格（TBD-12c）。
- 与其他组件关系：三者互斥显示，一次只显示一个。
- 现状：`PreviewView` 能力已由 `x-markdown-vue` 的 `MarkdownRenderer` 覆盖；`WysiwygView` 与 `SourceView` 不存在。
- 约束：导图导入后的数据格式与展示方式、代码块导入的语言与插入位置等细节仍待确认，不可自行决定，见第 7 节。

## 6. 状态管理

按现有技术栈（无 Pinia/Vuex）提出，不引入新状态库。如后续跨页面共享用户态，前端可另行评估是否引入 Pinia，但本次不做决定。

| `markdownMode` | `MarkdownReader` 内 `ref<'wysiwyg' \| 'source' \| 'preview'>` 或 `useMarkdownMode`，默认值 `'wysiwyg'` | 是（必须同步到 URL） | URL 参数命名与解析规则见 TBD-12b |
| `markdownDraft / dirty` | `MarkdownReader` 内状态 | 会话级保留 | 所见即所得（TinyMCE）与源码编辑的未保存状态；关闭前必须提示保存 |
| `networkError` | 页面级提示状态 | 否 | 网络断开或服务器崩溃直接提示网络错误；轮询防丢后续再做（TBD-12c） |
| `book / chapter / loading / error` | 沿用 `ChapterReaderView` 现有 `ref` | 否 | 已实现加载、404、错误、骨架屏 |
| `toast` | 沿用 `useToast` | 否 | 已实现 |

现有可复用能力：

- 路由参数 `bookId/chapterId` 驱动文档加载。
- `MarkdownRenderer` 的 `sanitize/GFM/Shiki` 渲染能力建议由预览模式复用。
- `ToastHost` 用于轻提示，不替代表单校验和错误页。

## 8. 浏览器验收测试用例

以下用例均可在桌面浏览器手工验证。凡标注“待确认”的步骤，需按第 7 节确认结果执行。

### TC-01 浏览器窗口与页面容器

1. 打开任意章节阅读地址，例如 `/books/frontend-rendering/chapters/rendering-pipeline`。
2. 页面外壳正常显示，无全局报错。
3. 页面容器内同时存在文件资源管理器多功能栏和 Markdown 阅读主区，默认进入所见即所得模式。
4. 通过标准为：布局无重叠，多功能栏默认展开，左上角三条线入口可见，缩放至 `1280px` 与 `980px` 宽度下主区仍可阅读。

### TC-02 多功能栏收起

1. 点击多功能栏收起控件或左上角三条线入口。
2. 多功能栏以平滑滑动过渡隐藏。
3. 左上角三条线入口保持可见。
4. 阅读主区横向扩展且内容可继续浏览。
5. 通过标准为：收起过程有平滑滑动过渡；收起后入口可见可点击；阅读内容无丢失、无控制台报错。

### TC-02b 文件导入

1. 点击文件资源管理器左下方小 `+` 号按钮，选择文件。
2. 通过标准为：文件出现在文件树中，点击可打开。
3. 将单个文件拖入编辑框，弹窗询问是否导入，确认后导入，取消后不导入。
4. 将文件夹拖入资源管理器，弹窗询问是否导入，确认后导入，取消后不导入。
5. 多功能栏为空时直接空白，不展示占位。
6. 通过标准为：确认/取消行为符合 FR-03b；导入失败按 TC-11 提示。

### TC-02c 文件保留与关闭保存提示

1. 打开文件并编辑但不保存，刷新页面，已打开文件保留。
2. 关闭页面，浏览器必须提示是否保存该文件。
3. 选择保存后按后端协同接口传输文件到数据库持久化（接口见 TBD-14b）。
4. 移动端打开页面，多功能栏默认收起；桌面端默认展开。

### TC-03 多功能栏展开

1. 在收起态点击左上角三条线入口。
2. 多功能栏以平滑滑动过渡重新出现，左上角入口保持可见。
3. 左上角入口位于顶部绝对左上角；Logo 位置默认空白并预留形状与按钮。
4. 阅读主区恢复到展开态布局。
5. 在展开态再次点击左上角三条线入口，多功能栏可再次收起。
6. 重复收起/展开 3 次，布局保持一致。
7. 通过标准为：每次切换均符合 IR-01/IR-02/IR-02b；收起/展开均有平滑滑动过渡；无错位、无残留遮罩。

### TC-04 用户栏与省略号按钮

1. 找到文件资源管理器底部用户栏。
2. 用户栏内可见省略号按钮。
3. 点击按钮后出现用户菜单。
4. 通过标准为：按钮可聚焦、可回车激活；菜单含“用户设置”和“个人信息”两个入口。

### TC-05 用户菜单关闭

1. 打开滑出面板。
2. 点击面板外部，面板直接关闭。
3. 重新打开面板，按 `Esc`，面板直接关闭。
4. 通过标准为：外点击与 `Esc` 均可关闭；阅读区状态不变；焦点管理暂不做。

### TC-06 进入用户设置页面

1. 打开用户菜单并选择“用户设置”。
2. 路由跳转到独立设置页（设置页详细内容待后续设计图，路径按 TBD-13b 确认结果执行）。
3. 在设置页选择浅色/深色/跟随系统预设，并上传一张图片作为自定义背景。
4. 返回阅读页。
5. 通过标准为：三种预设可切换；图片上传可用；保存、持久化与返回规则符合后续设计图（TBD-07b/TBD-13b）。

### TC-07 查看个人信息

1. 打开用户菜单并选择“个人信息”。
2. 路由跳转到独立个人信息页，字段与后端接口一致（TBD-08c）。
3. 返回阅读页。
4. 通过标准为：字段完整、无敏感信息泄露、返回后阅读态正常；用户数据来自后端接口。

### TC-08 三模式切换

1. 在阅读主区找到模式切换控件，确认默认高亮为所见即所得（TinyMCE 可编辑）。
2. 依次切换所见即所得、源码、预览。
3. 检查 URL 同步记忆当前模式，刷新后恢复同一模式。
4. 检查所见即所得工具栏含加粗/斜体（“加细”落为斜体）、导入导图、导入代码块。
5. 通过标准为：一次只显示一个模式；当前模式高亮正确；同一文档在三个模式下对应一致；所见即所得与源码可编辑，预览只读；URL 记忆模式可用；切换过程无空白页、无报错。

### TC-09 源码模式内容一致性

1. 切换到源码模式。
2. 核对源码文本与当前章节 Markdown 一致。
3. 编辑源码并保存（触发条件按 TBD-10b 确认结果执行），再用复制按钮复制源码。
4. 切换到预览模式核对渲染结果一致。
5. 通过标准为：内容一致；复制可用；保存成功提示与失败提示符合 TBD-10b/TBD-12b 确认结果。

### TC-10 异常与空态（沿用现有能力回归）

1. 访问不存在的章节地址，期望显示 404 或章节不存在态。
2. 模拟加载失败，期望显示错误态并可重试。
3. 通过标准为：现有 `ChapterReaderView` 的 `loading/not-found/error` 行为不退化。

### TC-11 网络错误与保存（新增，已明确）

1. 断开网络或模拟服务器崩溃后执行保存。
2. 通过标准为：直接提示网络错误；不丢失已有编辑态描述；轮询防丢机制后续再做（TBD-12c）。
