## 1. 通用约定

### 1.1 服务地址

| 项目 | 值 |
|---|---|
| 本地地址 | `http://localhost:8080` |
| Context Path | 无 |
| 请求 Content-Type | `application/json` |
| 响应 Content-Type | `application/json;charset=UTF-8` |

### 1.2 统一响应结构

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | `number` | 业务状态码，与 HTTP 状态码保持一致 |
| `message` | `string` | 提示信息 |
| `data` | `object \| array \| null` | 业务数据；失败时为 `null` |

> 说明：后端已将统一响应字段调整为 `message`，前端 `ApiResponse` 类型同步更新，不再使用 `msg`。

### 1.3 鉴权

需要登录的接口必须携带 Token：

```http
Authorization: Bearer <token>
```

登录接口已实现：`POST /api/auth/login`，请求体为 `{"username":"...","password":"..."}`，成功后返回 `token`、`tokenType`、`expiresIn` 和 `user`。详见 `docs/api/backend-api-v1.0.md` 的 4.6 节。

| Header | 必填 | 说明 |
|---|---|---|
| `Authorization` | 是 | `Bearer` + 空格 + JWT Token |

- “当前用户”由 Token 解析得到。
- 请求中不传 `userId`，服务端不得信任客户端传入的用户 ID。
- Token 缺失、格式错误、无效或过期，统一返回 `401`。

### 1.4 时间与 ID

- 时间格式：`yyyy-MM-dd HH:mm:ss`，例如 `2026-10-28 10:00:00`。
- 时区：`Asia/Shanghai`。
- ID 类型：`number`（数据库为 `BIGINT UNSIGNED`）。
- 若未来 ID 超出 JavaScript 安全整数范围，需要统一改为字符串传输。

## 2. 接口定义

### 接口名称：获取当前用户的文件列表

### 请求地址

```http
GET /api/files/list
```

### 鉴权要求

必须携带 Token。

```http
Authorization: Bearer <token>
```

### 请求参数

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `page` | `int` | 否 | `1` | 页码，从 1 开始，必须大于等于 1 |
| `size` | `int` | 否 | `10` | 每页数量，范围 1-20 |

请求示例：

```http
GET /api/files/list?page=1&size=10 HTTP/1.1
Host: localhost:8080
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

### 业务范围

- 返回当前 Token 对应用户的全部文件。
- 包含 `PUBLIC` / `PRIVATE`、`DRAFT` / `PENDING` / `PUBLISHED` / `REJECTED` 全部状态。
- 排序：按 `updated_at DESC` 降序；同一时间按 `id DESC` 兜底，保证分页顺序稳定。
- 不分页返回用户信息，只返回文件列表。
- 本接口返回完整列表字段，B 端可直接使用。
- C 端如复用该接口，只展示 `updatedAt`（最晚修改时间）和本地编辑器的“是否已保存”状态；该状态由前端比较当前内容与最后保存快照得到，不由本接口返回。
- 若 C 端不应获取 `originalName`、`fileSize` 等字段，建议单独提供 C 端接口，不要在同一接口按角色裁剪响应，避免契约不稳定。

### 成功响应示例（HTTP 200）

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "total": 25,
    "records": [
      {
        "id": 1001,
        "title": "前端渲染笔记.md",
        "originalName": "rendering.md",
        "fileSize": 10240,
        "createdAt": "2026-10-28 10:00:00",
        "updatedAt": "2026-10-28 12:30:00"
      }
    ]
  }
}
```

### 成功响应字段说明

#### `data`

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `total` | `number` | 否 | 当前用户的文件总数 |
| `records` | `FileListItem[]` | 否 | 当前页文件列表；无数据时为 `[]`，不能为 `null` |

#### `FileListItem`

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | `number` | 否 | 文件 ID |
| `title` | `string` | 否 | 文件标题 |
| `originalName` | `string` | 是 | 原始文件名 |
| `fileSize` | `number` | 否 | 文件大小，单位字节 |
| `createdAt` | `string` | 否 | 创建时间，格式 `yyyy-MM-dd HH:mm:ss` |
| `updatedAt` | `string` | 否 | 最晚修改时间，格式 `yyyy-MM-dd HH:mm:ss`；C 端以此作为“最后修改时间” |

> 列表只返回展示所需字段；完整文件信息由文件详情接口获取。

### 失败响应示例

#### Token 无效、缺失或过期（HTTP 401）

```json
{
  "code": 401,
  "message": "登录已过期，请重新登录",
  "data": null
}
```

#### 参数错误：`page` 小于 1（HTTP 400）

```json
{
  "code": 400,
  "message": "页码不能小于1",
  "data": null
}
```

#### 参数错误：`size` 超出范围（HTTP 400）

```json
{
  "code": 400,
  "message": "每页数量必须在1-20之间",
  "data": null
}
```

#### 参数格式错误：非整数（HTTP 400）

```json
{
  "code": 400,
  "message": "参数格式错误：page",
  "data": null
}
```

#### 服务器内部错误（HTTP 500）

```json
{
  "code": 500,
  "message": "服务器内部错误",
  "data": null
}
```

### 参数校验规则

| 参数 | 规则 | 失败提示 |
|---|---|---|
| `page` | 必须是整数，且 `>= 1` | `页码不能小于1` |
| `size` | 必须是整数，且在 `1-20` 之间 | `每页数量必须在1-20之间` |
| `page` / `size` | 必须是合法整数 | `参数格式错误：page` / `参数格式错误：size` |

- 参数为空时使用默认值。
- 不采用“非法值自动纠正为默认值”的策略；非法值直接返回 `400`。
- 错误响应中的 `code` 与 HTTP 状态码一致。

### 错误码汇总

| HTTP | `code` | 场景 | `message` |
|---|---|---|---|
| `200` | `200` | 查询成功 | `success` |
| `400` | `400` | 页码小于 1 | `页码不能小于1` |
| `400` | `400` | 每页数量超出范围 | `每页数量必须在1-20之间` |
| `400` | `400` | 参数不是整数 | `参数格式错误：page` / `参数格式错误：size` |
| `401` | `401` | Token 缺失、无效或过期 | `登录已过期，请重新登录` |
| `500` | `500` | 服务端异常 | `服务器内部错误` |

## 3. 前端 TypeScript 类型定义

```ts
export interface ApiResponse<T> {
  code: number
  message: string
  data: T
}

export interface FileListItem {
  id: number
  title: string
  originalName: string | null
  fileSize: number
  createdAt: string
  updatedAt: string
}

export interface CurrentUserFileListData {
  total: number
  records: FileListItem[]
}

export type CurrentUserFileListResponse = ApiResponse<CurrentUserFileListData>

export interface CurrentUserFileListQuery {
  page?: number
  size?: number
}
```

请求示例：

```ts
export async function fetchCurrentUserFiles(
  token: string,
  params: CurrentUserFileListQuery = {},
): Promise<CurrentUserFileListResponse> {
  const query = new URLSearchParams()
  query.set('page', String(params.page ?? 1))
  query.set('size', String(params.size ?? 10))

  const response = await fetch(`/api/files/list?${query.toString()}`, {
    headers: {
      Authorization: `Bearer ${token}`,
    },
  })

  return response.json() as Promise<CurrentUserFileListResponse>
}
```

## 4. 与当前后端实现的差异

改造前已有接口为（现已移除）：

```http
GET /api/files/user/{userId}?pageNum=1&pageSize=10
```

它与本契约的差异如下，落地本契约时需要改造：

| 项目 | 改造前实现 | 本契约（已实现） |
|---|---|---|
| 请求路径 | `/api/files/user/{userId}` | `/api/files/list` |
| 鉴权 | 无 | 必须携带 Token |
| 用户来源 | 路径参数 `userId` | Token 解析 |
| 分页参数 | `pageNum` / `pageSize` | `page` / `size` |
| 每页上限 | `100` | `20` |
| 响应字段 | 原为 `msg` | 已统一为 `message` |
| 时间格式 | 原为 ISO-8601 | 已统一为 `yyyy-MM-dd HH:mm:ss` |
| 分页信息 | 返回 `pageNum`、`pageSize`、`pages` | 只返回 `total`、`records` |
| 非法分页值 | 自动归一化为默认值 | 返回 `400` |
| 权限控制 | 任意 `userId` 可查 | 只能查当前 Token 用户 |

2. **[已完成]** 新增 `GET /api/files/list`，从 Token 获取 `userId`。
3. **[已完成]** 调整分页参数为 `page` / `size`，非法值返回 `400`。
4. **[已完成]** 调整响应字段为 `message`，时间格式化为 `yyyy-MM-dd HH:mm:ss`。
5. **[已完成]** 按本契约裁剪列表字段，并补充前端类型。
6. **[已完成]** 旧接口 `GET /api/files/user/{userId}` 已移除。

## 5. 已确认规则

1. 列表默认按 `updated_at DESC` 降序，`id DESC` 兜底。
2. `size` 默认 `10`，上限暂定 `20`，后续根据展示效果再调整。
3. B 端返回完整列表展示字段；C 端只展示 `updatedAt` 和“是否已保存”。
4. 旧接口不长期双轨：无调用方时直接移除；有调用方时标记废弃并保留一个版本。

## 6. 历史文件列表方案建议

用户登录后查询历史文件用于继续编辑，这个方向是合理的，建议按下面的边界实现：

- **从 Token 取用户**：使用 `GET /api/files/list`（或语义更明确的 `/api/files/mine`），不再传 `userId`，避免越权查询。
- **列表保持轻量**：列表只返回 `id`、`title`、`originalName`、`fileSize`、`createdAt`、`updatedAt` 等元数据；Markdown 正文、图片数组进入编辑器后再调详情接口，避免列表接口返回大字段。
- **B/C 端分开**：B 端管理列表需要状态、可见性、创建时间等管理字段，C 端当前用户列表只需要 `updatedAt` 和本地保存状态。不要把“按角色返回不同结构”塞进同一个接口，否则字段契约会越来越难维护。
- **“是否已保存”不要硬塞进服务端字段**：
  - 如果指编辑器里“当前内容是否已保存”，这是前端本地 dirty 状态，由当前内容与最后保存快照比较得出；服务端无法知道用户还没提交的修改。
  - 如果指跨设备/服务端的保存状态，需要新增草稿或自动保存版本模型（例如 `lastSavedAt`、`contentVersion`），另立契约，不能简单返回一个恒为 `true` 的 `saved`。
- **旧接口的定位**：`GET /api/files/user/{userId}` 暴露用户 ID、无鉴权、可被任意调用方查询，不适合作为长期方案；当前已直接移除，统一使用 Token 版本。
- **路径选择**：`/api/files/list` 可以使用；如果希望更贴近 REST 语义，`/api/files/mine` 更清晰，但需要同步修改文档和前端调用，不影响本契约其他部分。
