## 2. 本次实际调用的接口（全部已实现）

### 2.1 公开文件分页

```http
GET /api/files?pageNum=1&pageSize=9&keyword=xxx&category=技术随笔
```

- 前端函数：`fetchPublicFiles`（`frontend/src/api/public.ts`）
- 后端：`FileController.page`，`@OptionalAuth`，匿名可读
- 固定条件：`visibility = 'PUBLIC' AND status = 'PUBLISHED' AND node_type = 'FILE'`
- 排序：`created_at DESC, id DESC`
- 用途：右侧文章列表唯一数据源；`keyword` 对应 `title LIKE`；`category` 为分类精确匹配（`UNCATEGORIZED` 表示未分类）；总数 `total` 显示在右上“共 N 篇”

响应 `data.records[]` 即 `FileVO`：

| 字段 | 类型 | 页面用途 |
|---|---|---|
| `id` | `number` | 卡片 `key`，`/read/:id` 跳转 |
| `title` | `string` | 卡片标题 |
| `coverUrl` | `string \| null` | 卡片封面，有则显示 64×64 缩略图 |
| `fileSize` | `number` | 格式化为 B / KB / MB |
| `updatedAt` | `string` | `yyyy-MM-dd` 更新日期；也用于种类分组 |
| `createdAt` | `string` | 保留，未直接展示 |
| `userId` | `number` | 保留，未直接展示 |
| `originalName` | `string \| null` | 保留 |
| `mdUrl` | `string` | 不在列表页使用 |
| `storageProvider` | `string` | 不在列表页使用 |
| `visibility` / `status` | `string` | 后端已固定为 PUBLIC / PUBLISHED |
| `category` | `string \| null` | 卡片分类标签 |
| `summary` | `string \| null` | 卡片摘要；后端未填写时按正文自动生成 |
| `authorNickname` | `string \| null` | 作者昵称；为空时用 `authorUsername` 兜底 |
| `authorUsername` | `string` | 作者登录用户名 |

### 2.2 公开文章分类及数量

```http
GET /api/files/categories
```

- 前端函数：`fetchPublicFileCategories`（`frontend/src/api/public.ts`）
- 后端：`FileController.categories`，`@OptionalAuth`，匿名可读
- 用途：左侧“文章的种类”列表与全量计数

响应 `data` 为 `FileCategoryVO[]`：

| 字段 | 类型 | 页面用途 |
|---|---|---|
| `category` | `string \| null` | 分类名；`null` 表示未分类，前端展示“未分类” |
| `count` | `number` | 该分类下公开已发布文章总数（全量统计，非本页） |

### 2.3 登录态（侧栏底部用户栏复用工作台逻辑）

| 接口 | 前端函数 | 用途 |
|---|---|---|
| `POST /api/auth/login` | `loginUser`（经 `LoginDialog`） | 登录后可进工作台发布 |
| `GET /api/auth/me` | `fetchUserMe` / `ensureSession` | 刷新后恢复 `UserBar` |
| `GET /api/auth/captcha` | `fetchCaptcha`（`LoginDialog` 内 `LoginForm`） | 注册/登录验证码 |
| `POST /api/auth/register` | `registerUser` | `LoginDialog` 内“去注册~” |

字段复用 `UserVO`：`id`、`username`、`nickname`、`avatar`、`role`、`status`、`createdAt`、`updatedAt`。

## 3. 设计图诉求与后端对应情况（v1.7 已全部落地）

| drawio 诉求 | 后端现状（v1.7） | 页面实现 |
|---|---|---|
| 文章的种类真实分类 | `files.category` 字段 + `GET /api/files/categories`；`GET /api/files` 支持 `category` 筛选 | 按后端返回的分类列表展示，切换分类时向后端重新请求 |
| 文章摘要 | `files.summary` 字段；未填写时由服务端按正文自动生成 | 卡片展示 `summary`，为空则不显示 |
| 文章作者 | `FileVO.authorNickname` / `authorUsername`，由 `user` 表联查派生 | 卡片展示昵称，为空时用用户名兜底 |
| 种类计数全量统计 | `GET /api/files/categories` 返回 `[{ category, count }]`，为全量计数 | 分类按钮显示“共 N 篇” |
| 文章封面 | 列表已有 `coverUrl`（取 `images[0].url`） | 有封面显示 64×64 缩略图，无封面纯文字卡 |
| 文章页面内直接阅读正文 | 列表只给元数据 | 点击卡片进 `/read/:id`，正文由 `GET /api/files/{id}` ＋ `GET /api/files/{id}/content` 加载，无需新接口 |

> 分类筛选的 URL 参数约定：`kind=all` 不出现在 URL；选择具体分类时 `kind` 为分类名；未分类使用 `kind=UNCATEGORIZED`，后端对应筛选 `category IS NULL OR category = ''`。

## 4. URL 参数

| 参数 | 来源 | 说明 |
|---|---|---|
| `q` | 侧栏搜索 | 同旧版，按标题模糊搜索 |
| `kind` | 种类按钮 | `all`（默认，不出现在 URL）/ 分类名 / `UNCATEGORIZED`，刷新保留 |

## 5. 验收

- 侧栏搜索、种类切换、分页、空态、错误重试、收起/展开、移动端抽屉均走现有接口。
- 登录框与 `UserBar` 沿用工作台逻辑，不新增鉴权接口。
- 后端分类接口不可用时，页面自动回退为按 `updatedAt` 分组（全部 / 最近 7 天 / 最近 30 天 / 历史），不影响列表可用性。
